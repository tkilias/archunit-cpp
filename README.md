# archunit-cpp

`archunit-cpp` aims to help C++ projects enforce architectural rules through pytest. Its current direct-include check is a proof of concept for that broader goal.

## Current capability

The plugin provides an `assert_include` fixture. It checks whether a source file directly includes a header whose resolved path ends with the suffix you specify. A transitive include does not satisfy the assertion.

To use it, the Python environment needs pytest and Python bindings for libclang. The build directory for the C++ project must contain `compile_commands.json`, generated by the build system with the correct compiler and include flags. Each source file being checked must have one matching compile command in that database.

Install the project with its pytest plugin extra:

```sh
pip install "archunit-cpp[pytest-plugin]"
```

For a source checkout, install the local project instead:

```sh
pip install ".[pytest-plugin]"
```

Then use the fixture in a pytest test:

```python
def test_main_includes_api(assert_include):
    assert_include("build", "src/main.cpp", "demo/api.hpp")
```

The fixture uses the compile command for `src/main.cpp` to parse that translation unit with libclang. It fails if the compilation database or source cannot be parsed, if there is not exactly one matching compile command, or if the expected header is not directly included.

## Project direction

The direct-include assertion is the first building block for a broader C++ architecture testing toolkit. The intended future use is to let teams express dependency and layering rules as tests alongside their code, then apply those rules consistently as the toolkit grows. The current release focuses on checking direct header dependencies; broader architecture rules are future work.
